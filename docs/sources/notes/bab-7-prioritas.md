# Bab 7 — Prioritas

**Photo files:** p072–p080
**Printed pages seen:** 127–128, 192–205

## What it establishes

- **Scarcity forces choice.** Priority exists because resources (time, money,
  energy) are limited. Without deliberate prioritisation, circumstances set your
  priorities instead of you. *(p072)*
- **Priorities are revealed by accumulation.** What you actually give your time
  and money to is your real priority, regardless of what you say. *(p072–p073)*
- **A modified Eisenhower matrix**, and the modification is the interesting part.

### The book's modification *(p073–p077)*

It rejects "important / not important" as the axis, because in ordinary usage
"important" already means "affects my goal". Under that reading, unimportant
things should never enter the to-do list at all — so a 2×2 on importance is
really a 1×2 plus a bin.

It replaces the axis with two variables:

| Variable | Guiding question | Yes | No |
|---|---|---|---|
| **Significant** | How much does this move the goal? (Pareto) | top 80% of impact | bottom 20% |
| **Crucial** (can only you do it?) | Could someone else do this well? What is the cost if not you? | only you | delegable |
| **Urgent** | How close is the deadline? | near | none |

Filtering order: not significant → discard; significant but delegable →
delegate; significant and only-you → to-do list. Then order the to-do list by
urgency. *(p078)*

Priority 2 (urgent but not significant) gets an explicit warning: reconsider
whether it needs doing at all, because it competes with priority 3 (significant,
not urgent), which is where goals actually get met. *(p078)*

It also adds a fourth lever the classic matrix lacks: **automate** — if
something is significant and recurring, look for technology before doing it by
hand. *(p079)*

## Assessment

The modification is a real improvement on the popular Eisenhower matrix, because
it replaces a vague axis with a question that has an answer. But the *product*
value is still limited:

- The 2×2 itself is better on paper. Nobody opens an app to plot four boxes.
- The genuinely software-shaped problem underneath is **selecting a subset under
  a capacity constraint**: "from these 12 items, which 3 fit in the hours I
  actually have?" That is a different decision *shape*, not a later stage of the
  CBA pipeline.
- The book's own filter is a decision tree with three binary inputs, which is
  easy to implement and easy to explain — but it produces a quadrant, not an
  ordering, and users will ask for the ordering.

## Maps to our framework

Not a pipeline stage. It is an **alternative decision shape** (`prioritas`),
entered from the start rather than reached mid-pipeline. This matches the
`prioritas` class already in the System One question set.

## Primary source

Covey, *The 7 Habits of Highly Effective People* (1989) — popularised Eisenhower.
Academic grounding for the 2×2 is weak; the defensible formalisation is
scheduling/selection under a capacity constraint, plus opportunity cost.

## Do not copy

The warteg-owner framing, the specific Priority 1–4 wording, the "automast"
term.

## Engine relevance

**Medium, as a second decision shape.** Ship after the CBA pipeline works. Do
not ship the quadrant alone — ship the subset selection, which is what the user
actually cannot do on paper.
